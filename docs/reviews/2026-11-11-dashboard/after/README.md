# Результат исправления личного кабинета

Реализован [план](/workspace/Platform-Delovoy/docs/requirements/2026-11-11-dashboard-fixes-plan.md) по десяти проблемам исходного ревью. Устройство API, правила действий и определение событий: [архитектурное решение](/workspace/Platform-Delovoy/docs/architecture/2026-11-11-customer-dashboard.md). Связь фактов, улучшений и будущей оценки: [гипотезы](/workspace/Platform-Delovoy/docs/reviews/2026-11-11-dashboard/hypotheses.md).

## Изменения

Кабинет разделён на обзор, бронирования, заказы, обращения и профиль. На обзоре видны ближайшие визиты и заказы в работе. История больше не вытесняет предстоящие брони; списки имеют пагинацию и не показывают удалённые записи. Заказы раскрывают состав и количество единиц; обращения — полный текст и переписку с корректными авторами, с возможностью ответить.

У брони появились детали и доступные действия с серверной проверкой владельца. Сохраняются действующие правила штрафов, переноса, акцепта и ограничений Плей Парка. Нельзя получить полную платёжную ссылку после частичной оплаты, при расхождении суммы со скидкой или для прошедшего визита. Принятые на месте деньги не описываются как отсутствие оплаты.

Формы корректно показывают ошибки и успешное сохранение. Ошибка чтения уведомлений не подменяется включенными галочками. Имя обновляется в профиле, сессии и шапке; неподдерживаемой привязки Яндекса нет. Подтверждение email проходит по ссылке без ручного токена; есть повтор при сбое. Диалог отвязки управляет фокусом; формы переносят действия на узком экране.

Добавлены события кабинета и отдельный блок в `/admin/analytics`. Он показывает количество событий и аккаунтов по типам, не называет независимые счётчики когортной конверсией и не смешивает их с покупательскими воронками. Продовые данные не выгружались, внешний счётчик не перенастраивался. Новая статистика начнёт накапливаться после выпуска изменения.

## Проверки

| Проверка | Результат |
|---|---|
| Полный Vitest | 449 файлов, 5810 тестов прошли. |
| Заключительные целевые проверки | 13 тестов в 4 файлах прошли после последних изменений; включают дополнительную проверку текста об оплате на месте и совместимый BigInt в тесте агрегатов. |
| Браузерные регрессии | Все 5 сценариев `e2e/dashboard.spec.ts` прошли на локальном Chromium, в том числе повторно против production standalone-сервера: мобильные формы, диалог, ошибки чтения/записи, email, права доступа. |
| Сквозная запись в БД | Подтверждены ответ на обращение, имя и шапка, настройки, отмена брони, действительная email-ссылка и запись событий. Только отдельная локальная база с вымышленными данными. |
| Агрегаты аналитики | Авторизованный локальный SUPERADMIN получил HTTP 200, 10 типов записанных событий и московскую временную зону; таблица отобразилась в админке. |
| Production build | `npm run build` завершился успешно, включая проверку типов приложения. |
| Lint | Успешно: 0 ошибок, 74 предупреждения общего набора. |
| Общий `npm run typecheck` | Первоначально обнаружил TS2367 в прежней проверке `NODE_ENV=staging`. Для релизного QA проверка приведена к строке без изменения логики выбора staging. Повторная команда завершилась успешно для приложения и бота. |

Браузерный прогон использовал установленный `/usr/bin/chromium`: стандартная ревизия браузера Playwright в окружении отсутствует. Платёжные сценарии проверены на правах, согласиях и суммах через тесты; реальное списание денег и внешняя отправка писем не выполнялись.

При подготовке CI выявлены и устранены отдельные причины нестабильности E2E.
Установка системных библиотек Playwright дважды падала на DNS Ubuntu-зеркал:
теперь тесты запускаются в официальном noble-образе с уже установленными
браузерами и библиотеками, версия совпадает с установленным `@playwright/test`.
Runner для сборки закреплён на Ubuntu 24.04. Набор тестов и обязательность
проверок сохранены. Локаторы даты беседок выбирают видимую форму, исключая
скрытую streaming-копию Next.js. Сценарий Плей Парка выбирает следующий день
от даты формы: после 21:00 UTC прежнее «завтра UTC» совпадало с текущим днём
парка в Москве, поле не менялось и тест ожидал несуществующий запрос.
Проверка фотографий столов читает непустой список видимых изображений одним
снимком DOM: удаление скрытой streaming-копии больше не оставляет устаревшие
индексы локаторов между получением списка и чтением атрибутов.
