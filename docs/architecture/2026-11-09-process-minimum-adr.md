# ADR 2026-11-09 — Процесс разработки: необходимый минимум

**Статус:** принято владельцем.
**Заменяет:** ADR `2026-05-21-dev-velocity`, `2026-08-10-autonomous-issue-cleanup`,
`2026-08-11-backlog-intake`, `2026-08-14-autonomous-dev-pipeline-audit`,
`2026-08-20-owner-out-of-github`, `2026-08-24-remove-migration-width-holds`.
Они удалены из `docs/`, история осталась в git.

## Контекст

За полгода вокруг кода выросла процессная автоматика, и её стало больше, чем самих фич:

- **39 workflow-ов.** Из них 10 обслуживали AI-автоочередь: свипер авто-мержа каждые 15 минут, грумер раз в час, auto-rebase, merge-gate, блокировка нативного auto-merge, обработка Dependabot, backlog-intake, вечерний дайджест, eval агентов и ci-watchdog. Ещё около 12 были разовыми ops-скриптами, которые уже отработали.
- **Около 7 тыс. строк скриптов** (очередь, intake, agent-pipeline) и около 4,6 тыс. строк тестов к ним.
- **Модули `owner-decisions`** (таблица, API, команда бота `/decisions`) и **`pipeline-metrics`**.
- **Шум в GitHub.** Очередь стояла на паузе (`enabled: false`), но её heartbeat был встроен в `/api/notifications/health`. Без heartbeat health отвечал 503, site-watchdog раз в 5 минут заводил issue `notifications-down`. Итог: 313 таких issues за всё время. Из 61 issue за последний месяц 50 завёл бот, и заметная часть открытых задач чинила саму автоматику.
- **Правила в пяти местах:** CLAUDE.md, AGENTS.md, DEVELOPMENT-RULES.md, `agents/`, `.claude/agents/`. Они противоречили друг другу, например в стеке было записано «Next 15».

## Решение

Оставляем только то, без чего нельзя безопасно выпускать код.

1. **Мерж руками.** PR, зелёный CI, мерж делает человек. Автоочередь, гейт, свипер, auto-rebase и контур owner-decisions удалены вместе с кодом. Таблица `OwnerDecision` удалена миграцией `20261109000000_drop_owner_decisions`: в ней были только служебные записи автоматики, бизнес-данных не было.
2. **CI на PR:** Lint, Test, TypeScript Check (теперь проверяет и Telegram-бот), Build Docker Image, E2E, migrations-drift. Удалены джобы, которые никогда не падали: `security` (`continue-on-error`), Trivy (`exit-code: 0`), `ac-traceability`, а также дублирующая `lockfile`.
3. **Мониторинг пишет только в Telegram.** site-watchdog (проба, ремедиация по SSH), deploy-error-budget (авто-откат при ×5 ошибок), disk-space-monitor и docker-cleanup остаются. GitHub-issues они больше не создают. ci-watchdog удалён: о красном CI GitHub уведомляет сам.
4. **Dependabot** приходит раз в месяц: один групповой PR minor+patch на npm и один на Actions. Мажоры не предлагаются.
5. **release-please** остаётся. Release-PR мержим руками, когда нужен релиз с анонсом.
6. **Ручные ops-инструменты** работают только по `workflow_dispatch`. Push-триггеры с не-main веток убраны. Разовый ops-workflow удаляется следующим PR после применения.
7. **Один источник правил — CLAUDE.md**, раздел «Процесс». AGENTS.md — короткий указатель. AI-агенты в `.claude/agents/` самодостаточны и используются по желанию, обязательного конвейера с артефактами в `docs/qa-reports` и `docs/context` больше нет.

## Последствия

- **Нет авто-мержа.** PR ждёт человека. Это осознанная цена: каждый мерж в `main` уходит в прод.
- **Нет автоматического превращения прод-ошибок и фидбека в issues.** Сигналы остаются в Telegram, на дашборде мониторинга (`SystemEvent`) и в разделе фидбека в админке.
- **Cron GitHub ненадёжен.** С 2026-11-01 GitHub запускает cron-workflow репозитория пачками раз в 4–8 часов. Поэтому `site-watchdog` (`*/5`) на деле не даёт пятиминутного покрытия. Поминутный надзор обеспечивает `scripts/local-watchdog.sh` (cron на самом VPS), а site-watchdog служит внешней проверкой «по возможности». Разбор — инцидент 2026-11-06, удалён вместе с owner-decisions, есть в истории git (PR #1188).
- **Пропало «✅ сайт снова доступен».** Раньше это сообщение отправлялось при закрытии issue `site-down`. Если сайт починился сам после неудачной ремедиации, отдельного уведомления не будет. Алерт об автоматическом восстановлении остаётся.
- **Остались внешние хвосты**, которые снимаются в настройках GitHub, а не кодом:
  - секреты `OWNER_DECISIONS_SECRET` и `QUEUE_MERGE_TOKEN`;
  - лейблы `auto:*`, `batch`;
  - «призрачные» workflow-ы со старых веток;
  - открытые issues, заведённые автоматикой.
