# ADR 2026-11-09 — брони лично каждому, отчётность по умолчанию, еженедельные подсказки бота

Статус: принято (запрос владельца 2026-11-09).
Связано: ADR `2026-08-13-miniapp-role-rebuild`, `2026-10-25-team-access-notifications`,
PRD `2026-10-24-telephony-daily-summary-prd`.

## Контекст — почему владелец «не получал отчётность»

Аудит модуля `notifications` и `analytics/business-reports.ts` показал:

1. **Недельный бизнес-отчёт** (`analytics.business_weekly`) был строго opt-in:
   без строки `NotificationEventPreference(enabled=true)` планировщик никому
   ничего не слал. Включить его можно было только на отдельной странице
   `/webapp/business-analytics`, в Центре уведомлений его не было.
2. **Сводка звонков** (`telephony.daily_summary`) по PRD 2026-10-24 — только
   карточка в ленте Mini App, без сообщения бота. Кто не открывает ленту, её
   не видит.
3. **Брони**: лично сотрудникам приходили только `booking.created/cancelled` и
   только при явной подписке или из списка получателей раздела; остальное — в
   групповой чат. «Бронь по телефону», перенос, «скоро закончится» видел только
   канал смены (`dispatchModuleChannel`).
4. Личные сообщения из `notifyAdmin` уходили с HTML групповой версии: каналы
   `dispatch()` экранируют текст, и сотрудник видел `<b>…</b>`, `<a href=…>` и
   заголовок `[gazebos] booking created`.

## Решение

### 1. Путь доставки «по умолчанию» (`default`)

`ManagedEvent.defaultEnabled: true | "superadmin"` в каталоге стал настоящим
путём доставки в едином резолвере (`audience-rules.ts`): нет строки
предпочтения → событие включено (для всех с доступом к категории или только
для SUPERADMIN); явная строка (вкл/выкл) всегда сильнее. Экраны (Центр,
страница сотрудника, матрица) считают той же функцией — тумблер честный,
подпись «Включено по умолчанию — можно выключить».
`staffAudience: "personal"` теперь означает «индивидуальные пути» —
личная подписка **или** default; список раздела и роль не участвуют.
Категория может ограничить роли (`roles`) — «Отчётность» только SUPERADMIN/ADMIN,
как `getBusinessViewer`.

### 2. Брони — все лично, каждый настраивает сам

Категория «Бронирования»: `booking.created`, `booking.admin_created`,
`booking.rescheduled`, `booking.cancelled` — по умолчанию «Вкл» для всех, у кого
есть раздел (SUPERADMIN, ADMIN по роли, MANAGER с грантом/назначением);
`booking.ending_soon` — opt-in. Новые для персонала события помечены в
`EVENT_ROUTING` как `staff: "direct"`: только индивидуальные пути, без группового
чата и SSE (у канала смены своя копия). Групповой чат раздела работает как
раньше и от личных тумблеров не зависит. `booking.confirmed` и `booking.paid`
лично не шлём — они дублируют «Новую бронь (оплачена)» и `payment.succeeded`.

Личное сообщение собирается из HTML-шаблона в чистый payload
(`staff-payload.ts`): первая строка — заголовок, ссылки — кнопки.

Маркер `booking.ending_soon` теперь пишется для любой брони: у клиента без
канала лог был SKIPPED, и сообщение повторялось каждые 5 минут.

### 3. Отчётность

- `analytics.business_weekly` в каталоге (категория «Отчётность»),
  `defaultEnabled: "superadmin"`; планировщик и экран бизнес-аналитики берут
  получателей из того же резолвера. Финансовый доступ по-прежнему перепроверяется
  `getBusinessViewer` перед отправкой.
- `telephony.daily_summary_telegram` — копия сводки звонков сообщением бота,
  `defaultEnabled: "superadmin"`, отдельный тумблер; карточка в ленте —
  без изменений (это отступление от «0 внешних отправок» PRD 2026-10-24 по
  прямому запросу владельца). Только агрегаты, без номеров и имён. Claim
  `NotificationLog` на (день, человек) — один раз в день, без повторных запросов к
  Novofon (берём снимок из карточки ленты, если он есть).

### 4. Еженедельные подсказки и новости (`system.weekly_digest`)

Всем пользователям Mini App, включая гостей: вторник после 12:00 МСК, не чаще
раза в неделю (claim `weekly-digest:<user>:<понедельник>`), до 120 сообщений за
прогон пятиминутного крона.

Уровни доступа:
- гость (USER) — только публичная подсказка (`CLIENT_TIPS`) и заголовки
  публичных новостей (`BroadcastCampaign` сегмента `all_verified_users`, их и так
  видит вся лента); ни ссылок на `/admin`, ни релизов;
- сотрудник — плюс подсказка по одному из **своих** разделов
  (`computeAdminSections` по ролям и грантам, перечитанным из БД) или по Mini App,
  и заголовки завершённых релизов недели (`system.release` сотрудникам уже приходит);
- влитые аккаунты, не запускавшие бота и заблокировавшие его — не получают.

Отписка — тумблер «Подсказки и новости» в «Профиль → Уведомления и каналы»,
строка `NotificationEventPreference(userId, system.weekly_digest)`. Тип не в
каталоге сотрудников (он общий для всех ролей и не идёт через `dispatch()`).

## Последствия

- Сотрудники с доступом к броням начнут получать личные сообщения о бронях без
  каких-либо действий; кто в групповом чате — может выключить дубль в Центре.
- Владелец (SUPERADMIN) получает недельный бизнес-отчёт и ежедневную сводку
  звонков в Telegram, если бот запущен и у него есть Telegram-канал.
- Открытый вопрос (юристу): новости парка в еженедельном сообщении гостю могут
  считаться рекламной рассылкой. Сейчас — opt-out, как и существующие рассылки
  `all_verified_users`; переключить на opt-in — одна строка в `loadCandidates`.

## Обновление 2026-11-09 (второй запрос владельца)

### 5. У ADMIN и SUPERADMIN включено всё

Новое значение `defaultEnabled: "admins"` — включено у ADMIN и SUPERADMIN, у
MANAGER — по подписке. Им помечены все события каталога, у которых не было
более широкого флага: кафе, аренда, платежи, Авито, «Релизы платформы»,
«Бронь скоро закончится», недельный бизнес-отчёт (теперь и ADMIN с доступом к
аналитике). Брони (`true`) остаются включёнными и у MANAGER с разделом, сводка
звонков в Telegram — только у суперадмина. Доступ не расширяется: событие
приходит, только если у человека есть его раздел; явное «выкл» по-прежнему
сильнее. Инвариант держит тест в `audience-rules.test.ts`.

### 6. Разовый анонс команде

`staff-launch-announcement.ts`: каждому ADMIN и SUPERADMIN, запустившему бота, —
одно сообщение «уведомления теперь приходят сюда, лишнее выключайте в Центре
уведомлений». Строки текста — только по категориям, к которым у человека есть
доступ (`hasEventAccess`). Один раз на человека (claim
`staff-announce:notifications-launch-2026-11:<user>` в `NotificationLog`),
только 09:00–21:00 МСК и до 13.11.2026. После окна модуль инертен и удаляется
следующим PR — как разовый ops-скрипт.
