# ТЗ дизайнеру: бизнес-аналитика Делового

## Задача
Администратор с analytics-grant и суперадминистратор должны за минуту понять: сколько денег зарегистрировано, где изменился спрос, какие данные неполны и куда перейти для действия. Архитектура: ../architecture/2026-10-31-business-analytics.md; независимая оценка: ../analytics/2026-10-31-business-capability-review.md. Отдельная страница `/admin/analytics/business`, ссылка из существующей рекламы. Существующий стиль zinc/white, emerald/blue, Tailwind, без новых библиотек. Дизайнер делает реальный React интерфейс.

## Компоновка
- Заголовок «Бизнес-аналитика», строка периода «завершённые дни · МСК», 7/30/90 дней, обновить, CSV, печать (визуальный отчёт); связь с `/admin/analytics` рекламой.
- Четыре KPI: учтённые поступления, возвраты, корректировки, нетто. Сравнение с предыдущим равным периодом, абсолютная дельта; без процентов от нулевой базы.
- Читаемый график ежедневных поступлений/возвратов с доступной таблицей-расшифровкой; отрицательное нетто не обрезать.
- Направления: Барбекю Парк, Плей Парк, Кафе; деньги, брони/завершения/отмены/неявки/заказы, связанные заказы, известные/повторные клиенты. Видимое предупреждение о неполном кассовом покрытии.
- Воронка по направлениям: просмотры/начало/отправка/оплата, с точным описанием разных единиц visitor-day/entity. Это шаги периода, не когорта. Офисы: отдельная приглушённая карточка «Демонстрационные данные — исключены». Парковка/сауна: денежные данные не подключены.
- Реклама/сайт отдельно: общесайтовые визиты и расход (включают офисные страницы/кампании, не прибавляются к B2C итогам). Недоступное = «Нет данных», не 0; нет ROAS/прибыли.
- Блок качества и методики: источники, время обновления, ограничения, число исключённых/дублированных проводок. Статусы загрузка/ошибка/пусто.
- Telegram: личная недельная сводка, toggle OFF по умолчанию, пн 09:00 МСК за предыдущую неделю; тестовая отправка на текущий подтверждённый аккаунт; состояние канала и доставки. В Mini App `/webapp/business-analytics`: тот же отчёт/переключатель через apiFetch из TelegramProvider, ссылка из настроек только staff с analytics и ролью ADMIN/SUPERADMIN. На мобильном удобные карточки, не широкая обязательная таблица.

## Контракт разработчику
Использовать типы `src/modules/analytics/business-types.ts`.
Web API GET `/api/analytics/business?period=7d`, GET/PUT `/api/analytics/business/subscription` body `{enabled:boolean}`, POST `/api/analytics/business/test` body `{requestId:UUID}`, GET `/api/analytics/business/export?period=7d`. Все ответы apiResponse envelope; CSV скачивается авторизованным fetch.
Mini App те же пути с префиксом `/api/webapp/business-analytics` (основной GET, /subscription, /test; без export). Все финансы приходят только после серверного допуска. UI не является security boundary.

## Приёмка
Desktop 1440 и mobile 390px: нет горизонтального переполнения страницы; keyboard/focus/aria для controls и графика; ошибки не показывают устаревший период; тест/переключатель disabled пока запрос выполняется; успешная отправка только при sent=true; нет финансовых данных в localStorage или публичном изображении.
