## Баги

Блокирующих (blocker/major) нет; security-кейсов с FAIL нет.

### BUG-1 (Minor): заголовок `Referrer-Policy: no-referrer` у `/r/[code]` перекрыт глобальным
- **Где:** `src/app/r/[code]/route.ts:24` (задан `no-referrer`) ↔ `next.config.ts:7` (глобальный `Referrer-Policy: strict-origin-when-cross-origin`); в проде ещё `infra/nginx/delovoy-park.conf:98` (`add_header … always`).
- **Шаги:** запустить приложение, получить валидную ссылку (`NotificationLink`), `fetch("/r/<code>", { redirect: "manual" })`.
- **Ожидалось (ADR §Q4):** `Referrer-Policy: no-referrer`.
- **Фактически:** `Referrer-Policy: strict-origin-when-cross-origin`; остальные заголовки (`Cache-Control: no-store, private`, `Location`, 302) верны.
- **Влияние:** эксплуатируемого нет — на кросс-доменную цель (t.me) уходит только origin без кода; на свою цель — first-party. Unit-тест роута смотрит заголовки обработчика и перекрытия не видит.
- **Рекомендация:** либо более специфичное правило для `/r/:path*` в `next.config.ts`/`location /r/` в nginx, либо поправить ADR и убрать мёртвый заголовок.

### BUG-2 (Minor, Should): AC-C3.4 — «У вас пока нет разделов» недостижимо
- **Где:** `src/modules/notifications/webapp-center.ts:254` (`emptyState` только при `categories.length === 0`) + категория `system` с `staffAlways` (`src/modules/notifications/catalog.ts:172`).
- **Шаги:** MANAGER без единого `AdminPermission` и без назначений открывает Центр Mini App → `GET /api/webapp/notification-center`.
- **Ожидалось (AC-C3.4):** сотруднику без разделов показано «У вас пока нет разделов. Обратитесь к суперадмину».
- **Фактически:** `categories: ["system"]`, `emptyState: null` — виден только блок «Системные → Релизы». Для любого сотрудника «Системные» есть всегда, так что условие не срабатывает никогда; unit-тест проходит на моке резолвера без `system`.
- **Влияние:** экран не пустой, но пояснения нет; AC уровня Should.
- **Рекомендация:** считать «пусто» по категориям без `staffAlways` (или показывать сообщение рядом с «Системными»).

### BUG-3 (Minor, существующий паттерн): `PATCH /api/users/[id]/notify-releases` — невалидный JSON даёт 500
- **Где:** `src/app/api/users/[id]/notify-releases/route.ts:34` (`await request.json()` внутри общего `try`, `catch` → `500 INTERNAL_ERROR`). Файл изменён этим PR, паттерн унаследован.
- **Шаги:** SUPERADMIN: `PATCH /api/users/<id>/notify-releases` с телом `{not json`.
- **Ожидалось:** 400/422 `VALIDATION_ERROR` (так отвечают остальные 8 мутирующих маршрутов PR).
- **Фактически:** `500 {"error":{"code":"INTERNAL_ERROR","message":"Ошибка обновления настроек"}}` (stack/пути не раскрываются).
- **Рекомендация:** вынести `request.json()` в отдельный `try` с `apiValidationError("Некорректный JSON")`.

### Nit
- **N-1** `docs/releases/2026-10-25-team-access-notifications.md:75-76`: «ссылки … в ленте Mini App идут через короткий адрес `/r/…`» — по ADR §Q4 и коду лента измеряется через `POST /api/webapp/feed/open`, `/r` только для Telegram/Push/Email.
