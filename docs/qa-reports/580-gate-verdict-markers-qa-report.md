## Независимая security-проверка (не пересказ ревью раунда 1/2)

- Сам сходил в GitHub API (не MCP-кеш, не доверие code-reviewer'у) за реальными комментариями PR
  #632: `curl .../issues/632/comments` → тела `claude[bot]` действительно приходят с
  `author_association: "CONTRIBUTOR"` — тем же уровнем, что у любого стороннего аккаунта с одним
  смерженным PR. Это подтверждает и обосновывает решение фильтровать по логину, а не по
  `author_association` — без этого фильтр `MEMBER`/`COLLABORATOR` или `authorAssociation-only`
  пропустил бы `claude[bot]`, а с `CONTRIBUTOR`-only пропустил бы и спуфера.
- `isTrustedVerdictAuthor` перечитан (`scripts/lib/issue-queue.ts`): `OWNER` → true,
  `TRUSTED_VERDICT_LOGINS.includes(login)` (`claude[bot]`) → true, всё остальное → false.
  Юнит-тесты покрывают явную попытку спуфинга (`CONTRIBUTOR` без известного логина → false,
  `COLLABORATOR`/`MEMBER` без известного логина → false, пустой логин → false).
- `comment()` (постит вердикт) и `allComments()` (читает для гейта) используют один и тот же
  REST-эндпоинт (`/repos/{repo}/issues/{num}/comments`) — маркер, поставленный `verdict`,
  гарантированно виден `gate`/`automerge`. Не review-треды (`/pulls/.../reviews`), это осознанно
  задокументировано в коде.
- Самосогласованность: `HOLD_PATTERNS` (`scripts/lib/issue-queue.ts:400-408`) содержит
  `^scripts\/lib\/issue-queue\.ts$` и `^scripts\/issue-queue\.ts$` — оба файла в дифф-стате этого
  PR. Перечитал регулярки и применил к своему собственному `git diff --stat` руками — этот PR
  сам обязан уйти в `hold` (рубильник) независимо от вердиктов, что соответствует заявлению.
