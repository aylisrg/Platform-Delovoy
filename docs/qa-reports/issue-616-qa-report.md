## Пункт 2 задания — adversarial-тест на `.find()` с несколькими PR (свой, не из сьюта)
Прочитал предикат в `missedAutoCloseIssues` (`scripts/lib/issue-queue.ts:238-243`):
```ts
const pr = mergedPrs.find(
  (p) =>
    p.closesIssues.includes(issue.number) &&
    new Date(issue.updatedAt).getTime() <= new Date(p.mergedAt).getTime()
);
```
Временной гвард — **внутри** колбэка `.find()`, оба условия проверяются вместе на каждом элементе,
поэтому `.find()` физически не может «остановиться» на первом совпадении по `closesIssues`,
провалившем гвард по времени — он продолжит перебор до элемента, где выполняются оба условия.

Написал и прогнал (`npx vitest run`, временный файл в `scripts/__tests__/`, удалён после — `git
status` чист) 3 своих сценария поверх реальной `missedAutoCloseIssues`:
1. Старый PR (mergedAt раньше issue.updatedAt, гвард НЕ проходит) первым в массиве, новый PR
   (mergedAt позже, гвард проходит) вторым → результат корректно берёт новый PR (`prNumber: 701`),
   не проваливается в `undefined`/не берёт старый.
2. Тот же сценарий, но порядок в массиве обратный (новый первым, старый вторым) → тот же результат —
   порядок элементов не влияет на корректность (оба условия проверяются на каждом элементе).
3. Оба PR проваливают гвард по времени → результат пустой, несмотря на совпадение `closesIssues`.

Все 3 теста прошли на первом прогоне. Ответ на прямой вопрос задания: **гвард корректно находится
внутри предиката `.find()`**, сценарий с несколькими PR обрабатывается верно независимо от порядка.

## Пункт 4 задания — wiring `mergedAt: pr.merged_at as string`
`recentlyMergedPrs()` (`scripts/issue-queue.ts:135-146`) возвращает `out.filter((pr) =>
!!pr.merged_at)` — **не** типовой предикат (`pr is RawPr & {merged_at: string}`), а обычный
boolean-колбэк, поэтому TypeScript не сужает тип элементов после `.filter()`: возвращаемый тип
остаётся `RawPr[]`, с `merged_at?: string | null` как и был. В `cmdReconcile()` каст `pr.merged_at as
string` поэтому синтаксически обязателен — без него `mergedAt: pr.merged_at` не подошёл бы под
`MergedPrClosing.mergedAt: string`.

- **На рантайме каст безопасен**: `recentlyMergedPrs()` гарантированно отфильтровала falsy
  `merged_at` до того, как `.map()` в `cmdReconcile` до него доберётся — единственный вызывающий код,
  инвариант держится по построению.
- **На уровне тайпчекера — реальный, но не новый гэп**: экспериментально подтверждено (см. раздел
  «Регрессия» выше), что `npx tsc --noEmit` вообще не видит `scripts/` (exclude в `tsconfig.json`), то
  есть каст ничего не «прячет» от CI прямо сейчас, потому что CI и так не проверяет типы этого файла
  ни с кастом, ни без него. Если бы `scripts/` когда-нибудь включили в тайпчек, `as string` (а не
  типовой предикат в `.filter()`) остался бы единственной защитой инварианта — компилятор не поймает
  будущее ослабление фильтра в `recentlyMergedPrs()`. Технически более безопасным вариантом был бы
  типовой предикат в `filter()`, убирающий необходимость каста вовсе — но это стилистическая
  придирка (nitpick), не блокирующая находка: рантайм-инвариант держится, гэп в тайпчекинге
  pre-existing и не введён этим PR, PR и так идёт на `hold`-мерж под ручной просмотр владельца.

на ручной мерж владельца, как и задумано. Единственные находки — минорные, текстовые (неточное число
тестов в commit-message) и инфраструктурные pre-existing (scripts/ вне tsc-тайпчека) — ни одна не
представляет функциональной ошибки и не блокирует PASS.
