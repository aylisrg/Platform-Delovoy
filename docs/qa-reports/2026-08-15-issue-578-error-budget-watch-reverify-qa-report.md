## 2. БАГ-1 (был блокер) — независимая проверка через полный CLI-скрипт, не изолированный вызов функции

Собрал с нуля собственный fake-`curl` харнесс (роутинг по URL: `/compare/`, `/issues?state=open`, `POST /issues`),
поставил первым в `PATH`, прогнал **реальный** `npx tsx scripts/error-budget-watch.ts` (а не мок функции внутри
теста) с `DEPLOY_SHA=cafe0005... PREVIOUS_SHA="" BEFORE_COUNT=5 AFTER_COUNT=30` (before=5/after=30 → `×6` →
`action=rollback`, при этом `PREVIOUS_SHA` пуст — ровно сценарий БАГ-1).

Наблюдения из лога харнесса:
- `fetchCommits` корректно не сделал ни одного вызова к `/compare/` (previousSha=null) — 2 вызова всего: список
  открытых issues (дедуп) и `POST /issues`.
- `GITHUB_OUTPUT previous_sha=` — пусто, workflow не задиспатчит реальный откат (не изменилось, было верно и
  раньше).
- Тело созданного issue (извлёк из перехваченного `-d` тела POST-запроса, распарсил как JSON):
  ```
  ⚠️ **Авто-откат пропущен** — предыдущий успешный SHA не найден, нужна ручная проверка.
  ```
  Проверил программно: `'запущен' in body` → **False**, `` '`?`' in body `` → **False**, `` '`?' in body or '?`' in body `` → **False**, `'пропущен' in body` → **True**.

Это закрывает ровно ту находку: P0-issue больше не заявляет о выполняющемся необратимом действии, когда откат
реально пропущен. Текст теперь синхронизирован с формулировкой соседнего Telegram-шага.

Юнит-тест `error-budget.test.ts:144-162` независимо покрывает тот же сценарий на уровне `errorBudgetIssue()`
напрямую — совпадает с моей end-to-end проверкой.

## 3. Finding-2 (markdown injection, был minor/non-blocking) — структурная проверка через реальные CommonMark-рендереры, найден остаточный баг в самом фиксе

Не ограничился substring-проверкой из нового теста репозитория. Установил `markdown-it` + `commonmark`
(референсная реализация спецификации) в изолированный scratchpad-проект и прогнал **реальную**
`errorBudgetIssue()` из `scripts/lib/error-budget.ts` (импорт напрямую через `tsx`, не переписывал функцию).

**PoC-A (тот же класс, что в исходном Finding-2, но собственная формулировка)** — сообщение коммита
`` fix: `](evil)[click](url) `` — оба рендерера (`markdown-it`, `commonmark`) дают **ровно один** `<a href>`,
указывающий на настоящий commit-URL. Инъекция закрыта для этого случая — совпадает с заявленным.

**PoC-B (собственная гипотеза "alternate escape bypass", как и просила задача)** — сообщение коммита,
содержащее **уже существующий необработанный `\` непосредственно перед `]`**:
```
fix: weird case \](https://attacker.example/B)[click B](https://attacker.example/phishB
```
`escapeMarkdownLinkText` (`s.replace(/[[\]`]/g, '\\$&')`) экранирует найденный `]`, добавляя перед ним ещё один
`\`, не учитывая, что перед символом уже стоял `\`. Результат — `\\]` (два `\` + `]`). По CommonMark-спеке
экранирование разбирается слева направо попарно: `\\` — это экранированный литеральный обратный слэш,
а следующий за ним `]` **больше не экранирован** — закрывает `[...]` раньше времени.

Прогнал ровно этот вывод `errorBudgetIssue()` (полное тело issue, не изолированную строку) через оба
рендерера:
```
<a href="https://attacker.example/B">fix: weird case \</a>[click B](https://attacker.example/phishB](...)
```
`hrefs` в теле issue: `['https://attacker.example/B', 'https://x']` (второй — легитимная ссылка на run) —
**рабочая кликабельная ссылка на произвольный внешний URL внутри авто-созданного P0-issue подтверждена
структурно (парсинг реальным CommonMark-парсером, не грепом по подстроке)**, воспроизводится на обоих
независимых рендерерах.

**Классификация:** не блокирую вердикт этим находкой — тот же trust-boundary, что и у исходного Finding-2
(эксплуатация требует сообщения коммита, уже смерженного в `main`, т.е. уже высокого уровня доверия; исходный
отчёт по этой же причине не блокировал предыдущий проход). Фикс сузил поверхность атаки (простой PoC больше не
работает), но не закрыл её полностью для сообщений с "естественным" `\` перед спецсимволом.

**Рекомендация Developer'у (не блокирует, но стоит сделать в этом же PR или отдельным тикетом):** экранировать
сам `\` первым, до вставки экранирующих `\` перед `` [ ] ` ``:
```ts
function escapeMarkdownLinkText(s: string): string {
  return s.replace(/\\/g, '\\\\').replace(/[[\]`]/g, '\\$&');
}
```
Проверил этот вариант на PoC-B через тот же харнесс (commonmark) — даёт ровно один `<a href>` на легитимный URL,
инъекция закрыта.
