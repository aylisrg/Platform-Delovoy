# Review: chore(metrics) — телеметрия /next-issue для issue #753 (PR #769)

## Вердикт: PASS

## Контекст
Follow-up к PR #767 (код-фикс issue #753 — `ref: main` в checkout-шаге
`single-to-queue`, `.github/workflows/dependabot-automerge.yml`). PR #767
успел домержить свипер `issue-queue-merge.yml` раньше, чем сессия дошла до
штатного шага телеметрии (`.claude/commands/next-issue.md`, шаг 7) — коммит
metric-строки в ветку PR #767 стал невозможен (ветка закрыта). PR #769
добавляет ту же телеметрию отдельным коммитом прямо на `main` — это
предусмотренный runbook'ом сценарий гонки со свипером, только в обратную
сторону («не успела закоммитить метрику до чужого мержа» вместо «не успел
домержить»).

Для этого PR намеренно нет PRD/ADR — это не фича, а служебная запись в
JSONL-лог наблюдаемости пайплайна (`docs/pipeline-runs/next-issue.jsonl`,
источник `npx tsx scripts/issue-queue.ts metric`). Оцениваю по прямой
проверке диффа, а не по AC-таблице.

  `docs/pipeline-runs/next-issue.jsonl`.

## Валидность и соответствие схеме
- JSON синтаксически валиден (`node -e "JSON.parse(...)"`).
- Ключи и порядок ключей идентичны существующей строке #669
  (`ts,issue,branch,outcome,ci_fix_rounds,review_rounds,duration_min`) — оба
  объекта имеют одинаковую сигнатуру ключей.
- Схема соответствует `cmdMetric()` в `scripts/issue-queue.ts:799-830`:
  `outcome` — одно из `NEXT_ISSUE_OUTCOMES = ['merged','parked','blocked','released']`
  (использовано `merged` — валидно); `issue`, `ci_fix_rounds`,
  `review_rounds`, `duration_min` — числа (все целые, конечные).
- Значения перепроверены против фактической git-истории:
  - `branch: claude/issue-753-checkout-main-for-single-to-queue` — реальная
    ветка, существует локально, первый коммит `dcc4c98` («fix(ci): чекаутить
    main, а не merge-ref PR, в single-to-queue»).
  - Смержена как PR #767 в коммит `7bab0f2` с `Closes #753`.
  - `ts: 2026-08-25T04:09:13.168Z` — на 8 секунд раньше коммита самой
    телеметрийной строки (`5142854`, `04:09:21+00:00`) — согласуется с тем,
    что `metric` записывает timestamp перед `git commit`.
  - `duration_min: 24` — первый коммит ветки (`dcc4c98`, `03:50:54`) до
    мержа (`7bab0f2`, `04:07:53`) даёт ≈17 мин чистой работы над кодом;
    24 мин с учётом времени сессии на триаж/чтение issue до первого коммита
    — правдоподобно, не является аномалией и не влияет на корректность
    формата данных (это метрика длительности сессии, не только диффа).
  - `review_rounds:1`, `ci_fix_rounds:0` — согласуется с историей: в ветке
    #753 один коммит с ревью-артефактами (`70fac52`
    docs(qa): code-reviewer report — PASS с первого раза, без CI-фиксов) и
    один QA-коммит (`d10eea5`, тоже PASS) до мержа.
