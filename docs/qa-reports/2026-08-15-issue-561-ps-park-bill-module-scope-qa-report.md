# QA-отчёт: Issue #561 — GET /api/ps-park/bookings/[id]/bill не проверял requireAdminSection

**Ветка**: `claude/issue-561-ps-park-bill-module-scope`
**Коммит**: `9de7c914` (не запушен, 1 коммит поверх `main`, 2 файла, +36/-2)
**Тип задачи**: security fix (P2), точечный, повторяет эталонный паттерн из #560 (`bookings/[id]/route.ts`)

---

## Скоуп

Роут отдавал чек по брони ps-park (часы + позиции + суммы) любому пользователю с ролью MANAGER, не проверяя, назначен ли этот менеджер на модуль `ps-park` (`requireAdminSection`). Менеджер, привязанный только к другому модулю (например, `gazebos`), мог получить чек чужой брони ps-park, зная/подобрав её id — узкий, но реальный auth gap. Фикс добавляет `requireAdminSection(session, "ps-park")` сразу после проверки роли — тот же порядок вызовов, что и в уже одобренном `bookings/[id]/route.ts` (issue #560).

---

## Независимая проверка (не переповторение отчёта code-reviewer)

### 1. Функциональная проверка + мутационный тест (главное доказательство)

- Прогнал целевой файл тестов изолированно:
  `npx vitest run "src/app/api/ps-park/bookings/[id]/bill/__tests__/route.test.ts"` → **7/7 passed** (5 старых + 2 новых из этого коммита).
- Затем сделал мутационный тест: скопировал `route.ts` в бэкап, вручную убрал добавленные строки
  ```
  const denied = await requireAdminSection(session, "ps-park");
  if (denied) return denied;
  ```
  и перезапустил тот же файл тестов. Результат: **ровно 2 теста упали** (остальные 5 остались зелёными) —
  - `менеджер без гранта на модуль ps-park — requireAdminSection отклоняет, сервис не вызван (issue #561)` → `expected 200 to be 403`
  - `вызывает requireAdminSection с секцией ps-park` → `mockRequireAdminSection` вызван 0 раз вместо 1
  Это подтверждает, что тесты не тавтологичны и реально зависят от наличия вызова `requireAdminSection` в хендлере, а не от мока как такового.
- Восстановил `route.ts` из бэкапа, перепроверил `git status --short` (пусто, дифф от HEAD не изменился) и перезапустил тесты — **снова 7/7 passed**.
- E2E с реальным Postgres/сидом MANAGER-с-ModuleAssignment-только-на-gazebos не поднимал — размер фикса (2 строки логики, точная копия уже проверенного в #560 паттерна `requireAdminSection`, чья внутренняя логика уже покрыта своими unit-тестами в `lib/api-response`) не оправдывает эту затрату; мутационный тест на реальном хендлере даёт эквивалентную уверенность в данном случае.
