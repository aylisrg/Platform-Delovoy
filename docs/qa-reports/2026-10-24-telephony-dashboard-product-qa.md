# Product QA: статистика Novofon

Дата: 24 октября 2026. Основание:
`docs/requirements/2026-10-24-telephony-dashboard-prd.md`.

## Результат проверки по коду

Продуктовых блокеров в просмотренной реализации не осталось. Проверены
`dashboard-service.ts`, `dashboard-validation.ts`, маршрут dashboard,
`calls-dashboard.tsx`, `summary-card.tsx`, страница телефонии и подключение
к навигации. Это проверка поведения по коду; browser QA и прогоны тестов
отчитываются отдельно ведущим агентом и исполнителями.

| Требование | Наблюдение |
| --- | --- |
| Единый источник | Только `NovofonCall`; старый `CallLog` не прибавляется |
| Пропущенные | Только входящие с признаком потери |
| Неполные события | Входящие без потери и положительной длительности — «Уточняется» |
| Доля ответов | Принятые / (принятые + пропущенные); неизвестные исключены; без знаменателя «—» |
| Исходящие | Неудачный исходящий остаётся исходящим и имеет текст «без ответа» |
| Период | Сегодня/7/30 дней по МСК, граница начала следующего дня исключена |
| Журнал | Новые сверху; страницы по 25; номер маскируется до отправки в браузер; ссылки записей отсутствуют |
| Фильтры | Меняют журнал; сводка сохраняет весь период; смена фильтра/периода сбрасывает страницу |
| Ошибки | Ошибка не подменяется нулями; сохранённые данные при ошибке обозначены как потенциально устаревшие |
| Источник | Время последнего изменения журнала не называется успешной синхронизацией; настройка не объявляется проверкой доступности |
| Доступ | Страница, API и краткая карточка проверяют SUPERADMIN; на главном дашборде другие роли не читают журнал |
| Мобильная версия | Журнал представлен карточками, фильтры переносятся, результат подписан текстом |

## Найдено и исправлено в ходе проверки

1. Краткая карточка вела на `?filter=missed`, но экран сначала игнорировал
   параметр. Теперь страница валидирует фильтр и передаёт `initialFilter`.
2. Переход по KPI прокручивал страницу до запроса, после чего журнал
   исчезал при загрузке. Теперь сводка сохраняется при смене фильтра,
   журнал отдельно показывает загрузку, а прокрутка и фокус выполняются
   после появления нужного результата.

## Граница подтверждения актуальности

README и исторический QA-отчёт от 12 апреля описывают другую стадию
интеграции и не подтверждают её текущую работу. Код cron предусматривает
запуск каждые 10 минут; это не доказательство, что cron в production
установлен и успешен. Обновление экрана раз в минуту перечитывает локальный
журнал, не запрашивает свежий отчёт у оператора.

Доступные наблюдения окружения не содержат настроенных runtime credentials.
Production-данные и Novofon API не опрашивались. Поэтому допустимый итог:
«Интеграция реализована, раздел подготовлен, реальные цифры и связь в
production не проверены». Недопустимый итог: «Novofon работает, статистика
актуальна» без отдельной живой проверки.

Метрика `lastJournalUpdate` — время изменения отдельной записи. Она может
обновиться из-за webhook или повторной загрузки старой сессии и не является
ни heartbeat синхронизации, ни гарантией полноты журнала.

## Итоговая проверка реализации

Ведущий агент проверил завершённый дифф:

- `npm test`: 365 файлов, 5047 тестов, все прошли. Первичный запуск встретил
  sandbox `spawnSync bash EPERM` в существующих deploy-state tests; повтор
  с разрешённым окружением выполнил полный набор успешно.
- `npx tsc --noEmit`: успешно, ошибок нет.
- `npm run lint`: 0 ошибок, 76 существующих предупреждений; новые компоненты
  и backend дополнительно проверены адресно без замечаний.
- `git diff --check`: успешно.
- Chromium: действующий компонент с явно обозначенными демонстрационными
  данными в локальном Vite harness. Проверены смена периода, пропущенные,
  пагинация, ошибка с сохранённым снимком, отсутствие настройки и пустой журнал.
  Переход к пропущенным сохраняет фильтр и прокручивает заголовок журнала
  к верхней части экрана. Ошибок JavaScript нет.
- Визуально проверены desktop и мобильная тёмная тема. При ширине viewport
  390 px ширина документа также 390 px: горизонтального переполнения нет.

Browser-проверка использовала заглушку ответа API, не production-базу и не
авторизованный кабинет Novofon. Серверные проверки доступа покрыты unit-тестами.
Миграции и deployment не выполнялись.
