## Остаточный риск (честно, не замалчиваю)

Committed baseline PNG сгенерированы **не** тем Chromium, который реально установит CI
(`npx playwright install --with-deps chromium` в `.github/workflows/ci.yml` подтягивает rev 1234,
локально в песочнице доступен только rev 1194 — установка правильной ревизии заблокирована
прокси на уровне сети, не средствами сессии). Логика анти-флакинности (пункт AC2 выше) устраняет
недетерминизм *между прогонами одного и того же браузера* — она не гарантирует, что первый
прогон в CI будет побайтово совпадать с этими baseline, если рендеринг между ревизиями Chromium
(шрифты/AA/суб-пиксели) отличается на уровне, который дефолтный `threshold: 0.2` сочтёт значимым.
Это ровно тот риск, который явно обозначен в задании на проверку, и я не могу его закрыть из
песочницы — реальный GitHub Actions `e2e` job (устанавливает свой браузер с нуля, тот же
`ubuntu-latest`, что и в именах файлов `-chromium-linux.png`) — единственный источник истины по
этому конкретному пункту. Рекомендация: после мержа внимательно посмотреть на исход первого
CI-прогона; если diff есть — это ожидаемо и чинится штатным `npm run e2e:update-snapshots` в CI
том же окружении, а не признак сломанной логики теста.
