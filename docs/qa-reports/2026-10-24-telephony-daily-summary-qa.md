Тесты проверяют московскую границу 09:00 и завершённый отчётный день;
полный отчёт Novofon, нулевой день, некорректный ответ, пагинацию и усечение;
отсутствие публикации при ошибке/таймауте и повтор после ошибки; постоянный
ключ получатель+день, конфликт параллельных запусков, транзакцию с аудитом;
подписку по умолчанию, opt-out и повторную проверку роли после запроса API.

Проверки ленты включают объединение трёх источников, пагинацию, независимое
прочтение конкретной карточки, «прочитать всё» с временной границей,
непрочитанное, недоступность чужих записей и истории после понижения роли
или объединения аккаунта. Настройки не открывают категорию по старому
гранту/подписке, а внешний Telegram-канал для сводки не нужен.

## Поставка и ограничения

Изменение схемы вынесено в PR #1152 согласно правилу AGENTS.md для shared
инфраструктуры. Функциональный PR #1151 зависит от него. Порядок поставки:
#1152 (additive-таблица) → #1151 (scheduler, API ленты, UI).

Существующий cron уведомлений запускается раз в пять минут. После 09:00 МСК
публикуется вчерашний полный день; при сбое провайдера время публикации
сдвигается до успешной попытки. Без Data API token публикация пропускается.
Длительный простой не создаёт лавину старых уведомлений: восстанавливается
только вчерашний день. История — сохранённые снимки, а не живой журнал.

Проверки не обращались к production Novofon/БД и не отправляли реальные
сообщения. Production-миграция, deployment и запуск scheduler вручную
не выполнялись. Автоматическая публикация начнётся после доставки обоих PR
при настроенных Novofon Data API и существующем cron.
