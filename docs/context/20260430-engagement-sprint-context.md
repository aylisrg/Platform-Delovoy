## PO: Ключевые решения

### 1. Три фичи, не одна

Решено взять три фичи в один спринт (F1 профиль, F2 Telegram onboarding, F3 схемные фиксы). Обоснование: F1 и F2 технически связаны (US-3 профиля — это вход в F2), F3 — два небольших изменения, которые разблокируют аналитику для следующего аудита. Разбивать их на три отдельных спринта нецелесообразно.

### 2. H7 (funnel events) отложена

Добавление серверных `page.view` / `funnel.step` событий в `SystemEvent` или `AuditLog` — не берём. Yandex Metrika уже подключена server-side (commit adaa2cd). Когортная аналитика в БД нужна, но это отдельный PRD под Phase 5.3. В текущем спринте приоритет — устранить блокирующие проблемы активации.

### 3. Кафе-модуль (H6) — не берём

0 онлайн-заказов — диагностика неясна (нет events). Правильный порядок: сначала добавить `cafe.menu_view` события (H7), потом реагировать. Взять в кафе изменения сейчас — риск угадать не ту причину.

### 4. Модуль `profile` расширяется, не создаётся

`src/modules/profile/` уже есть. CLAUDE.md scope guard соблюдён — новый модуль не создаётся.

### 5. `cancelReason` — Zod enum, не DB enum

Поле в схеме уже `String?`. Не меняем тип на Prisma enum — сохраняем гибкость для будущего расширения причин без миграции. Enum-валидация только на уровне Zod в validation.ts.

### 6. `source` в `Booking` — server-side only

Поле `source` устанавливается исключительно на сервере на основе контекста вызова. Пользователь не может передать `source` в теле запроса. Это предотвращает подмену канала.
