## PO — Ключевые решения

**Решение 1: Модуль размещается внутри PS Park, не как отдельный top-level раздел.**
Абонементы — это функциональность PS Park (MVP). URL: `/admin/ps-park/subscriptions`. Это не общий механизм для всей платформы — generalization преждевременна. Когда понадобятся абонементы для беседок, будет отдельный PRD.

**Решение 2: Один активный абонемент на гостя — жёсткий инвариант.**
Ограничение упрощает логику менеджера (нет вопроса «с какого абонемента списывать?») и предотвращает ошибки учёта. Если в будущем понадобится несколько активных абонементов (например, разные типы — "вечерний" и "дневной"), это потребует отдельного PRD с обоснованием.

**Решение 3: `SubscriptionTransaction` — иммутабельный журнал.**
Записи транзакций не редактируются и не удаляются. Исправление ошибки = новая корректирующая запись. Это согласовано с паттерном `FinancialTransaction` в ps-park (тоже нет `updatedAt`). Audit trail должен быть неопровержим.

**Решение 4: Автосписание часов при завершении сессии — F7, не F6.**
F6 создаёт инфраструктуру и экспортирует `getActiveSubscriptionForUser`. F7 встраивает вызов в completion-логику сессии. Разделение позволяет запустить учёт абонементов вручную немедленно, а автоматизацию — следующим тикетом.

**Решение 5: Drill-down прошедших сессий — F7.**
Требование «видно что пил, что ел» — это связь `Booking → Order`. Реализуется в F7 одновременно с автосписанием, когда `bookingId` в `SubscriptionTransaction` начинает заполняться реальными значениями.

**Решение 6: Отмена абонемента — только SUPERADMIN.**
MANAGER может корректировать часы, но отмена — административная операция с финансовым подтекстом. Оставляем её за SUPERADMIN для снижения риска случайной отмены.

**Решение 7: Lazy auto-status (рекомендация для Architect).**
Проверка EXPIRED/DEPLETED — при чтении через `getActiveSubscriptionForUser`, не через постоянный cron. Это минимизирует инфраструктурную сложность на старте. Еженедельный cleanup-cron — для корректности фильтров в списке. Окончательное решение — за Architect.

**Решение 8: Decimal для hoursDelta.**
PS Park уже считает часы с точностью до 15 минут (шаг 0.25). Целое число минут создаст путаницу с отображением. Decimal(10,2) — единый формат для всего учёта времени в модуле.

**Решение 9: Запрет ухода remainingHours в минус — явная ошибка, не clamp.**
`INSUFFICIENT_HOURS` вместо автоматического обнуления. Менеджер должен осознанно ввести корректную цифру. Clamp мог бы скрывать ошибки учёта.

**Решение 10: Seed-файл для регистрации модуля.**
Запись `Module(slug="subscriptions")` создаётся через `scripts/seeds/subscriptions.ts` по правилам ADR-0001 (idempotent upsert). CLAUDE.md обновляется в том же PR (правило scope guard).
